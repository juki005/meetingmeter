# 4. Product Constraints

The implementation must preserve:

- organizer-owned meetings;
- authenticated access;
- private history;
- internal people;
- Guests;
- known and unknown Guest cost;
- explicit Start;
- participant ACTIVE/PAUSED/LEFT behavior;
- Resume;
- live elapsed time;
- live individual cost;
- live total estimated cost;
- explicit End;
- stable final result;
- receipt;
- history;
- PDF/Image/CSV export;
- estimate framing.

Unknown cost is **not zero**.

MeetingMeter is **not** an accounting, payroll, billing, or payment system.

---

# 5. Technical Implementation Baseline

Use:

- server-authoritative timestamps;
- interval-based participation measurement;
- meeting-level rate snapshots;
- explicit persisted state transitions;
- server-side authorization;
- stable finalized meeting records;
- export generation from finalized result data.

Do not use client-side counters as the authoritative financial calculation.

# 9. Do Not Do

Antigravity must not:

- start implementation before Stitch verification;
- invent missing visual details;
- infer product functionality from a visual element;
- convert unknown cost into zero;
- allow browser time to become financial source of truth;
- expose another user's private meetings;
- mutate finalized meeting results because profile data changed;
- silently change Product requirements;
- silently change approved Design requirements;
- mark APPROVED merely because implementation passes QA.
